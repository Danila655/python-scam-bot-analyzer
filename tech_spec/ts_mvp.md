# Техническое задание
## Игровой тренажёр «Кибердетектив: Распознай скам»

---

## 1. Общее описание проекта

Консольная игра на Python, обучающая пользователей распознавать мошеннические сообщения в интернете.

Игрок читает сообщения так, будто он получил их в чате. Его задача — определить, это скам или обычное безопасное сообщение. За каждый правильный ответ начисляются очки. За ошибку игрок теряет жизнь. В конце игры показывается итог, звание и основные признаки скама.

**Запуск игры:**

```bash
python main.py
```

---

## 2. Структура проекта

Проект состоит ровно из **5 файлов**. Файлы объединены так, чтобы проект могли параллельно делать **2 команды**.

```text
project/
├── data.py              — база сообщений и случайная выборка кейсов
├── config.py            — константы и настройки игры
├── rules_results.py     — правила игры и итоговый экран
├── question_answer.py   — показ вопроса, ввод ответа, проверка ответа и звание
└── main.py              — ядро: подключение всех файлов, игровой цикл и запуск
```

> Нельзя создавать дополнительные файлы без согласования.
> Каждый файл импортирует только то, что ему нужно.

## 3. Разделение задач на 2 команды

### Команда 1 — данные, настройки, правила и финал

Команда 1 отвечает за файлы:

```text
data.py
config.py
rules_results.py
```

Задачи команды 1:

- создать базу сообщений в `data.py`
- настроить игровые константы в `config.py`
- сделать приветственный экран с правилами в `rules_results.py`
- сделать итоговый экран в `rules_results.py`
- подготовить список признаков скама для финального экрана

Команда 1 не пишет игровой цикл и не проверяет ответы игрока.

### Команда 2 — игровой раунд, проверка ответа и ядро

Команда 2 отвечает за файлы:

```text
question_answer.py
main.py
```

Задачи команды 2:

- показать один вопрос игроку
- получить выбор игрока
- проверить ответ
- начислить очки или уменьшить жизни
- определить итоговое звание
- собрать все файлы в `main.py`
- реализовать основной цикл игры

Команда 2 не наполняет базу сообщений и не меняет игровые константы.

### Общий договор между командами

Команды должны заранее договориться об одинаковых именах функций и переменных.

Команда 1 предоставляет:

```python
data
cases
LIVES
POINTS
SCAM_SIGNS
show_rules()
show_results(correct, score, lives, total)
```

Команда 2 предоставляет:

```python
show_question(question_num, case, total, lives, score)
get_choice()
process_answer(player, case, lives, score, correct)
final_title(score, total)
game_loop()
play()
```

## 5. Файл `data.py` — база сообщений

### Назначение

Хранит все сообщения и формирует выборку для текущей игры.

### Импорты

```python
import random
```

### Что нужно реализовать

**Переменная `data`** — полный список всех сообщений.

**Переменная `cases`** — список из **20 случайных кейсов**, выбранных из `data` без повторений:

```python
cases = random.sample(data, 20)
```

Каждый словарь в `data` описывает одно сообщение:

| Ключ | Тип | Описание |
|---|---|---|
| `'text'` | `str` | Текст сообщения, которое видит игрок |
| `'is_scam'` | `bool` | `True` — это скам, `False` — безопасное сообщение |
| `'explanation'` | `str` | Объяснение, почему это скам или почему безопасно |

### Требования к содержимому

- минимум **100 сообщений** в списке `data`
- примерно половина сообщений должна быть скамом
- примерно половина сообщений должна быть безопасной
- скам-сообщения должны включать просьбы пароля, подозрительные ссылки, выигрыш приза, срочность, угрозы, просьбы данных карты
- безопасные сообщения должны включать игровые приглашения, напоминания, обычные вопросы и бытовые сообщения

### Пример одной записи

```python
{
    'text': 'Привет! Хочешь сыграть вместе в Minecraft?',
    'is_scam': False,
    'explanation': 'Безопасно. Обычное приглашение поиграть. Нет ссылок и просьб о данных.'
}
```

## 6. Файл `config.py` — константы

### Назначение

Хранит все настройки игры в одном месте. Если нужно изменить количество жизней или очков, меняется только этот файл.

### Импорты

Этот файл ничего не импортирует.

### Что нужно реализовать

| Имя | Тип | Значение | Описание |
|---|---|---|---|
| `LIVES` | `int` | `3` | Количество жизней игрока в начале |
| `POINTS` | `int` | `10` | Очков за один правильный ответ |
| `SCAM_SIGNS` | `list[str]` | список строк | Признаки скама для итогового экрана |

`SCAM_SIGNS` должен содержать не менее 5 строк.

Примеры признаков:

- просят пароль или код подтверждения
- слишком выгодное предложение
- искусственная срочность
- подозрительные ссылки
- просят данные карты

## 7. Файл `rules_results.py` — правила игры и итоговый экран

### Назначение

Отвечает за приветственный экран с правилами и финальный экран после завершения игры.

### Импорты

```python
from config import LIVES, POINTS, SCAM_SIGNS
from question_answer import final_title
```

### Функция `show_rules()`

**Принимает:** ничего

**Возвращает:** ничего

**Что должна делать:**

1. Вывести заголовок игры, обёрнутый в рамку из символов `=`
2. Объяснить игроку суть игры одним-двумя предложениями
3. Показать текущие значения `LIVES` и `POINTS`
4. Объяснить, какую клавишу нажимать: `1` — скам, `2` — безопасное сообщение
5. Дождаться нажатия Enter перед началом игры

**Пример вывода:**

```text
==================================================
   КИБЕРДЕТЕКТИВ: Распознай скам!
==================================================

Тебе будут показаны сообщения из интернета.
Определи: это СКАМ или безопасное сообщение?

Жизни: 3  |  За правильный ответ: 10 очков

  1 — это СКАМ
  2 — безопасное сообщение

Нажми Enter, чтобы начать...
```

### Функция `show_results(correct, score, lives, total)`

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `correct` | `int` | Сколько правильных ответов дал игрок |
| `score` | `int` | Итоговый счёт |
| `lives` | `int` | Сколько жизней осталось |
| `total` | `int` | Сколько вопросов было всего |

**Возвращает:** ничего

**Что должна делать:**

1. Вывести заголовок «ИТОГ» в рамке из `=`
2. Показать количество правильных ответов из общего числа
3. Показать итоговый счёт и оставшиеся жизни
4. Вызвать `final_title(score, total)` и вывести результат
5. Вывести список `SCAM_SIGNS`, каждый признак с новой строки

**Пример вывода:**

```text
==================================================
           ИТОГ
==================================================
Правильных ответов: 9 из 20
Итоговый счёт:      90 очков
Оставшиеся жизни:   2

КИБЕРДЕТЕКТИВ — отличный результат!

Главные признаки скама:
  - просят пароль или код подтверждения
  - слишком выгодное предложение
  - искусственная срочность
```

## 8. Файл `question_answer.py` — вопрос, ввод, проверка ответа и звание

### Назначение

Отвечает за всё, что связано с одним раундом: показывает сообщение игроку, получает ответ, проверяет его и определяет итоговое звание.

### Импорты

```python
from config import POINTS
```

### Функция `show_question(question_num, case, total, lives, score)`

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `question_num` | `int` | Номер текущего вопроса |
| `case` | `dict` | Словарь с данными вопроса из `data.py` |
| `total` | `int` | Сколько вопросов всего в этой игре |
| `lives` | `int` | Сколько жизней осталось |
| `score` | `int` | Сколько очков набрано на данный момент |

**Возвращает:** ничего

**Что должна делать:**

1. Вывести строку-статус: номер вопроса, общее количество, жизни, счёт
2. Вывести текст сообщения из `case['text']`

**Пример вывода:**

```text
==================================================
Вопрос 3/20  |  Жизни: 2  |  Счёт: 20
==================================================

Сообщение:
  Поздравляем! Вы выиграли iPhone! Введите данные карты.
```

### Функция `get_choice()`

**Принимает:** ничего

**Возвращает:** `bool`

`True` — игрок считает, что сообщение является скамом.

`False` — игрок считает, что сообщение безопасное.

**Что должна делать:**

1. Запросить у игрока ввод через `input()`
2. Если введено `'1'`, вернуть `True`
3. Если введено `'2'`, вернуть `False`
4. Если введено что-то другое, вывести подсказку и спросить снова
5. Использовать `.strip()`, чтобы пробелы по краям не мешали

Функция не завершается, пока не получит корректный ответ.

### Функция `process_answer(player, case, lives, score, correct)`

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `player` | `bool` | Ответ игрока |
| `case` | `dict` | Словарь вопроса |
| `lives` | `int` | Текущее количество жизней |
| `score` | `int` | Текущий счёт |
| `correct` | `int` | Текущее количество правильных ответов |

**Возвращает:** кортеж `(lives, score, correct)`

**Что должна делать:**

1. Сравнить `player` с `case['is_scam']`
2. Если ответ совпадает, вывести «ПРАВИЛЬНО!»
3. Если ответ совпадает, прибавить `POINTS` к счёту
4. Если ответ совпадает, увеличить `correct` на 1
5. Если ответ не совпадает, вывести «НЕПРАВИЛЬНО!»
6. Если ответ не совпадает, уменьшить `lives` на 1
7. В обоих случаях вывести объяснение из `case['explanation']`
8. Вернуть обновлённые значения `lives`, `score`, `correct`

### Функция `final_title(score, total)`

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `score` | `int` | Итоговый счёт игрока |
| `total` | `int` | Количество вопросов в игре |

**Возвращает:** `str`

**Логика определения звания:**

| Доля от максимума | Звание |
|---|---|
| 80% и выше | «КИБЕРДЕТЕКТИВ — отличный результат!» |
| от 50% до 79% | «ОСТОРОЖНЫЙ ПОЛЬЗОВАТЕЛЬ — неплохо, но есть куда расти.» |
| ниже 50% | «НОВИЧОК — не расстраивайся, теперь ты знаешь больше!» |

Максимальный счёт считается так:

```python
total * POINTS
```

Доля результата считается так:

```python
score / (total * POINTS)
```

## 9. Файл `main.py` — ядро игры

### Назначение

Точка входа. Импортирует все нужные части проекта, запускает игровой цикл и связывает файлы между собой.

### Импорты

```python
import random
import data
from config import LIVES
from rules_results import show_rules, show_results
from question_answer import show_question, get_choice, process_answer
```

### Функция `game_loop()`

**Принимает:** ничего

**Возвращает:** кортеж `(correct, score, lives, total)`

**Что должна делать:**

1. Скопировать список `data.cases` в новую переменную через `[:]`
2. Перемешать копию через `random.shuffle()`
3. Запомнить общее количество вопросов в переменной `total`
4. Задать начальные значения:
   - `lives = LIVES`
   - `score = 0`
   - `correct = 0`
   - `question_num = 0`
5. Перебрать все вопросы в цикле `for case in shuffled:`
6. Увеличить `question_num` на 1
7. Вызвать `show_question(...)`
8. Вызвать `get_choice()` и сохранить ответ игрока
9. Вызвать `process_answer(...)` и обновить `lives`, `score`, `correct`
10. Если `lives == 0`, вывести сообщение о завершении игры и выйти из цикла через `break`
11. Если жизни остались, дождаться нажатия Enter перед следующим вопросом
12. Вернуть `correct, score, lives, total`

### Функция `play()`

**Принимает:** ничего

**Возвращает:** ничего

**Что должна делать:**

1. Вызвать `show_rules()`
2. Вызвать `game_loop()` и сохранить результат
3. Вызвать `show_results(...)` с полученными результатами

В функции `play()` должна быть только сборка игры из готовых функций. Основную игровую логику нужно хранить в `game_loop()`.

### Запуск

Последняя строка файла:

```python
play()
```
